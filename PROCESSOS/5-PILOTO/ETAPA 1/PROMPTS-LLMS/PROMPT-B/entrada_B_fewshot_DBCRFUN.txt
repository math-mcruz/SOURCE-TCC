Papel: Analista de sistemas legados que documenta as regras de negócio de programas COBOL para a área de negócio de um banco.
Tarefa: Ler o programa COBOL fornecido e listar as regras de negócio que ele implementa.
Definição de regra de negócio: Tudo o que a área de negócio (gerente ou cliente do banco) entende. Detalhes de código que o pessoal de negócio não entenderia ficam de fora.

O que não listar:
- Tratamento de erro padrão e falhas técnicas de banco de dados ou de sistema (códigos de retorno, ABEND, rollback);
- Gravação de registros técnicos, de log ou de auditoria;
- Controle de concorrência e ordem técnica de atualização;
- Navegação de tela e teclas de função;
- Validação de formato do campo digitado: se o conteúdo é numérico, se há espaços no meio, se há mais de um ponto decimal, se o caractere de sinal é válido.

O que listar, mesmo sendo checagem de campo:
- A obrigatoriedade de um dado (o campo não pode ficar vazio);
- Restrições sobre o valor em si (por exemplo: limites mínimos ou máximos, ou a lista de valores aceitos para um campo).
Quando um mesmo teste cobre ausência e formato, a classificação segue o que o código testa: teste de tamanho zero ou de campo só com espaços é obrigatoriedade (listar); teste de valor numérico é formato (não listar), mesmo que a mensagem exibida peça para preencher o campo.

Escopo: liste apenas regras que dependem de uma decisão no código (IF, EVALUATE ou teste de um código de retorno). Cada regra corresponde a um caminho dessa decisão. Não liste atribuições de valores, preparação de dados para gravação ou envio, nem exibição de dados, quando não houver uma decisão associada. Dentro de um mesmo caminho de decisão, não crie uma regra para cada campo atribuído ou exibido: descreva a consequência principal.

Agrupamento: valores alternativos testados numa mesma decisão que levam à mesma consequência formam uma única regra. Em decisões aninhadas, cada regra descreve o caminho completo até a consequência final; não liste como regra um teste intermediário que apenas leva a outro teste.

Atomicidade: Uma regra por item, com uma condição e uma consequência. Uma regra composta deve ser separada em itens.
Ocorrências repetidas: Se a mesma regra aparece em mais de um ponto do código, cada ocorrência é listada separadamente, com o seu parágrafo.
Fidelidade: Listar só o que o código de fato implementa, e não o que seria esperado de um sistema bancário. Se o comportamento for ambíguo, dizer isso no item.
Linguagem: Cada regra é uma frase em linguagem de negócio, em português. A frase pode citar entre parênteses o campo, a condição ou o código do programa que sustenta a regra (por exemplo, o nome do campo testado ou o valor de um código de retorno).

Formato da resposta, sem nenhum texto antes ou depois da lista:
1. Regra: <frase em linguagem de negócio>
   Condição: <quando se aplica>
   Consequência: <o que acontece>
   Parágrafo: <nome do parágrafo ou seção COBOL>

   Condição: a leitura do registro do cliente retorna NOTFND
   Consequência: indicador de sucesso 'N' e código de falha '1'
   Parágrafo: UCV010 (UPDATE-CUSTOMER-VSAM)

              WHEN OTHER
                 MOVE 'Not Storm Drain     ' TO STORM-DRAIN-CONDITION

           END-EVALUATE.

           IF STORM-DRAIN-CONDITION NOT EQUAL 'Not Storm Drain     '
              DISPLAY 'DBCRFUN: Check-For-Storm-Drain-DB2: Storm '
                      'Drain condition (' STORM-DRAIN-CONDITION ') '
                      'has been met (' SQLCODE-DISPLAY ').'
           ELSE

              CONTINUE
           END-IF.

       CFSDD999.
           EXIT.


       ABEND-HANDLING SECTION.
       AH010.

           EXEC CICS ASSIGN ABCODE(MY-ABEND-CODE)
           END-EXEC.


           EVALUATE MY-ABEND-CODE
              WHEN 'AD2Z'

                 MOVE SQLCODE TO SQLCODE-DISPLAY
                 DISPLAY 'DB2 DEADLOCK DETECTED IN DBCRFUN, SQLCODE='
                    SQLCODE-DISPLAY

                 DISPLAY 'DB2 DEADLOCK FOR ACCOUNT '
                   HV-ACCOUNT-ACC-NO
                 DISPLAY  'SQLSTATE=' SQLSTATE
                        ',SQLERRMC=' SQLERRMC(1:SQLERRML)
                        ',SQLERRD(1)=' SQLERRD(1)
                        ',SQLERRD(2)=' SQLERRD(2)
                        ',SQLERRD(3)=' SQLERRD(3)
                        ',SQLERRD(4)=' SQLERRD(4)
                        ',SQLERRD(5)=' SQLERRD(5)
                        ',SQLERRD(6)=' SQLERRD(6)

              WHEN 'AFCR'
              WHEN 'AFCS'
              WHEN 'AFCT'
                 MOVE 'Y' TO WS-STORM-DRAIN
                 DISPLAY 'DBCRFUN: Check-For-Storm-Drain-VSAM: Storm '
                        'Drain condition (Abend ' MY-ABEND-CODE ') '
                        'has been met.'

                 EXEC CICS SYNCPOINT
                    ROLLBACK
                    RESP(WS-CICS-RESP)
                    RESP2(WS-CICS-RESP2)
                 END-EXEC

                 IF WS-CICS-RESP NOT = DFHRESP(NORMAL)
                    INITIALIZE ABNDINFO-REC
                    MOVE EIBRESP    TO ABND-RESPCODE
                    MOVE EIBRESP2   TO ABND-RESP2CODE
                    EXEC CICS ASSIGN APPLID(ABND-APPLID)
                    END-EXEC

                    MOVE EIBTASKN   TO ABND-TASKNO-KEY
                    MOVE EIBTRNID   TO ABND-TRANID

                    PERFORM POPULATE-TIME-DATE

                    MOVE WS-ORIG-DATE TO ABND-DATE
                    STRING WS-TIME-NOW-GRP-HH DELIMITED BY SIZE,
                       ':' DELIMITED BY SIZE,
                        WS-TIME-NOW-GRP-MM DELIMITED BY SIZE,
                        ':' DELIMITED BY SIZE,
                        WS-TIME-NOW-GRP-MM DELIMITED BY SIZE
                        INTO ABND-TIME
                    END-STRING

                    MOVE WS-U-TIME   TO ABND-UTIME-KEY
                    MOVE 'HROL'      TO ABND-CODE

                    EXEC CICS ASSIGN PROGRAM(ABND-PROGRAM)
                    END-EXEC

                    MOVE ZEROS      TO ABND-SQLCODE

                    STRING 'AH010 - Unable to perform Synpoint '
                       DELIMITED BY SIZE,
                       'Rollback.' DELIMITED BY SIZE,
                       ' Possible Integrity issue following VSAM RLS '
                       DELIMITED BY SIZE,
                       'abend.' DELIMITED BY SIZE,
                       'EIBRESP=' DELIMITED BY SIZE,
                       ABND-RESPCODE DELIMITED BY SIZE,
                       ' RESP2=' DELIMITED BY SIZE,
                       ABND-RESP2CODE DELIMITED BY SIZE
                       INTO ABND-FREEFORM
                    END-STRING

                    EXEC CICS LINK PROGRAM(WS-ABEND-PGM)
                           COMMAREA(ABNDINFO-REC)
                    END-EXEC

                    DISPLAY 'DBCRFUN: Unable to perform Synpoint '
                       'Rollback.'
                       ' Possible Integrity issue following VSAM RLS'
                       ' abend'
                       ' RESP CODE=' WS-CICS-RESP
                       ' RESP2 CODE=' WS-CICS-RESP2

                    EXEC CICS ABEND
                       ABCODE ('HROL')
                       CANCEL
                    END-EXEC

                 END-IF

                 MOVE 'N' TO COMM-SUCCESS
                 MOVE '2' TO COMM-FAIL-CODE

                 EXEC CICS RETURN
                 END-EXEC

           END-EVALUATE.

           IF WS-STORM-DRAIN = 'N'
              EXEC CICS ABEND
                 ABCODE( MY-ABEND-CODE)
                 NODUMP
                 CANCEL
              END-EXEC

           END-IF.

       AH999.
           EXIT.


       POPULATE-TIME-DATE SECTION.
       PTD10.

           EXEC CICS ASKTIME
              ABSTIME(WS-U-TIME)
           END-EXEC.

           EXEC CICS FORMATTIME
                     ABSTIME(WS-U-TIME)
                     DDMMYYYY(WS-ORIG-DATE)
                     TIME(WS-TIME-NOW)
                     DATESEP
           END-EXEC.

       PTD999.
           EXIT.
